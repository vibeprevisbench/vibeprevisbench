# Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `missing Python packages ...` | Install the requirements into the interpreter that runs the script: `python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt`, then run the script with `.venv/bin/python`. `yt-dlp` is optional: only YouTube and Bilibili media need it. |
| `docker is not on PATH` | The evaluation needs a Linux host with Docker: every task and every replay runs in its own container. Install Docker or move to a host that has it. Do not use `--backend local` instead: it runs the agent on the host, where it can read the hidden ground truth in `data/rubrics/`. |
| `the Docker daemon is not reachable` | Start Docker. Either add the user to the `docker` group (then log in again) or run as a user that may use Docker. Check with `docker info`. |
| Sandbox image build fails while downloading Blender | download.blender.org must be reachable. The build checks the tarball's sha256, so a proxy or mirror must deliver the identical file. Docker build needs `HTTP_PROXY`/`HTTPS_PROXY` configured for the daemon or passed as build arguments. |
| `Blender 5.2.2 does not start on this host` | Scoring runs the Blender binary copied from the sandbox image on the host. Install its libraries, e.g. on Debian/Ubuntu: `apt-get install libx11-6 libxext6 libxrender1 libxi6 libxfixes3 libxkbcommon0 libsm6 libice6 libgl1 libegl1 libglib2.0-0 libgomp1`. Or pass `--blender /path/to/blender-5.2.2/blender`. |
| `input media still missing ...` | Read `data/fetch_report.json`. Scan-dataset photos need an authorized local copy: `--fetch-arg=--datasets-root=/path`. YouTube and Bilibili need `yt-dlp` and may block datacenter IPs; run setup from a regular network, or pass a proxy with `--fetch-arg=--ytdlp-arg=--proxy=URL`. A source that has been deleted cannot be recovered; with `--skip-missing-media`, the run continues and the summary lists the skipped tasks. |
| `STOPPING: 3 tasks failed within 5 minutes without a solution` | The agent does not work in the container. Read the printed `agent_log.txt`. Typical causes: the credential variable is not exported in the shell that runs the script; a wrong model name; the endpoint is unreachable from the container (try `docker run --rm --network bridge vibeprevisbench-agent:claude-code curl -sI https://api.anthropic.com`); or a custom CLI is not on the login-shell `PATH`. Fix it, then run the same command again. |
| An agent reaches the time limit on most tasks | Check `agent_log.txt` for loops or a hung CLI. Raising `--time-limit` makes the run non-comparable with the paper. |
| `prepare failed` | Read `runs/NAME/<ID>/prepare_log.txt`. Usually the input media are missing (run setup), or a container with the same name is left over: `docker rm -f vpb-NAME-<id>`. |
| `... was started with another configuration` | The run name already belongs to another agent setup. Use a new `--name`. Use `--force-config` only for a change that cannot affect the agent, such as a corrected typo in a non-secret environment variable that was not used. |
| Replay reports `failed` for some tasks | Those deliveries did not pass the gates: the code does not run standalone, the video is incomplete, or the scene does not reopen. They score 0, as in the paper. `runs/NAME/<ID>/replay.json` and `replay/` show why. |
| Judge stage skipped | Neither `VPB_JUDGE_API_KEY` nor `GEMINI_API_KEY` is set in the script's environment. Export the key, then run `--stages judge,report` with the same `--tasks`. |
| Judge errors (HTTP 4xx/5xx) | Check `VPB_JUDGE_BASE_URL`, `VPB_JUDGE_MODEL` and `VPB_JUDGE_AUTH`. Finished tasks are kept, so rerun the judge stage. |
| Scores differ from a previous run by a few hundredths | Expected for replayed meshes; see `docs/reproducibility.md`. |
